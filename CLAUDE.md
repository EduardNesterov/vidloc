## Что это

Vidloc — локальный десктопный локализатор видео для macOS (Apple Silicon).
Перевод EN/RU/IT → украинский: субтитры и озвучка; в работе — удаление вотермарок и вшитых
субтитров. Всё работает офлайн, без отправки данных в сеть.

## Где мы остановились — reuse-first v1: ВСТРОЕНО в воркер

**Проблема:** профилировка инпейнта — **LaMa ≈ 94%** времени (декод/энкод/склейка ≈ 6%).
Имеет смысл сокращать только **число запусков LaMa**, а не ускорять её саму.

**Идея:** видео темпорально избыточно — фон за вотермаркой почти всегда виден в соседних
кадрах. Статичный угол-лого: LaMa один раз → дальше reuse. Для **временных** субтитров
чистый фон виден в паузах → плита **реальная** (не оценка) → потенциально ~0 LaMa.

**Урок прототипа:** авто-детекция «что и когда убирать» — хрупкая. **НЕ авто-детектить** —
движок ведём от **разметки пользователя** (регион + интервалы).

**Что реализовано (`vidloc/inpaint/lama_worker.py`, per-region, без motion-comp):**
- На каждый регион держим `plate` (чистый фон его рамки), `ref_ring` (снимок немаскированной
  каёмки вокруг рамки в момент захвата плиты), `seen`, `reuse_run`.
- Кадр, где рамка региона **не активна** → она реально видна → захватываем **реальную** плиту
  + свежий `ref_ring` (главный выигрыш для gated-субтитров).
- Кадр, где рамка **активна** и плита есть → сверяем текущую каёмку с `ref_ring`. Остаток мал
  (фон не сдвинулся) → заполняем из плиты, **без LaMa**. Остаток велик (движение/склейка/свет)
  → LaMa + переотметка плиты и `ref_ring`. Плиты нет → LaMa.
- Каёмка (`_ring`) — это «предохранитель» от артефактов вместо motion-comp. Кейфрейм-рефреш
  раз в `--reuse-keyint` reuse-ов (по умолчанию 120) против дрейфа.
- **LaMa гоняется по-регионным тайлам, а не по union-кропу.** ffmpeg-I/O по-прежнему режет
  один union-кроп (полнокадровый сырой пайп откатан — скачок `kernel_task`), но модель
  инпейнтит **тайл на регион** (box + `LAMA_CTX`=48 контекста), батчем по кадрам этого региона
  (группировка `pending` → `jobs[id(r)]` → `run_region_lama`). Так стоимость LaMa растёт по
  площади регионов, а не по описывающему прямоугольнику: при разбросанных регионах union почти
  весь кадр, а тайлы маленькие. Кадры эмитятся по порядку.
- Параметры воркера: `--reuse {0,1}` (0 = старое поведение, LaMa на каждый активный кадр),
  `--reuse-thresh` (0.02, mean|Δ| на каёмке 0..1), `--reuse-pad` (6), `--reuse-gap` (2),
  `--reuse-keyint` (120). `lama.py` пробрасывает reuse/thresh/keyint и логирует строку `STAT`.
  Тумблер reuse проброшен в GUI (`RemovalConfig.reuse`, чекбокс в шаге удаления, вкл. по
  умолчанию) → `inpaint_video` → `lama.py`. `lama.py` при падении воркера кладёт в текст
  ошибки хвост его вывода (раньше traceback глотался и в лог попадала одна строка).
- **Вся reuse-работа bbox-локальна** (`r["bb"]` = box+feather+ring): на 1440p кроп — это
  миллионы пикселей, и полнокадровые numpy-операции на регион были бы неподъёмны.
- Счётчики в `STAT`: `lama_reg`/`reuse_reg` (порегионные решения) + `gpu_frames` (кадров,
  реально ушедших в LaMa — это и есть драйвер времени) + `frames`.

**Баг, который правили (был краш на реальном прогоне):** `if r in active` — это проверка
вхождения по значению, а регион — dict с numpy-полями; когда у двух регионов **совпадают
`intervals`** (частый случай: два вотермарка на всё видео, или двухстрочная полоса субтитров),
`dict.__eq__` доходил до numpy-ключа и падал с «truth value of an array is ambiguous». Смоук на
1 регионе это не ловил. Заменено на список флагов `acts` (без membership по значению).


**Что реализовано:**
- `vidloc/inpaint/vision_text.py` — детектор текста через **Apple Vision** (Neural Engine,
  офлайн), из numpy-кадра в память (без PNG на диск). Standalone (без `vidloc`-импортов),
  воркер тянет его как **sibling** (`import vision_text`, т.к. запускается из своей папки).
  Нужен `pyobjc` (Vision+Quartz) в `.venv-inpaint` — **поставлен через `uv pip`** (в скрипт
  создания venv пока НЕ добавлено — см. «известный пробел»).
- Воркер: флаг `--text {0,1}` (+`--text-dilate` 4). `flush_batch` разведён на `flush_reuse`
  (старый путь, `--text 0`, без изменений) и `flush_text`. В text-режиме на каждый активный
  кадр: детект текста в боксе → тайл-маска глифов → батч по-кадровых масок через LaMa на тайле
  региона → композитим только пиксели текста. reuse в этом режиме отключён (маска мелкая,
  LaMa дёшева). При отсутствии pyobjc воркер падает с понятной ошибкой (→ fallback delogo).

**Замер (6-с обрезка `For Test.mp4`, рамка на «Fake button gang» поверх лого Jeep, scale=2):**
`--text 1` → 360 кадров за ~26 c, текст стёрт, **лого/фактура руля сохранены** (у прямоугольного
затирания на том же месте — мыло). Детект отработал в 358/360 кадрах.

**Глифовая маска (шаг 2) — СДЕЛАНО:** `vision_text.glyph_mask()` внутри каждого найденного
word-бокса заливает **сами штрихи** через морфологический **tophat/blackhat** (opening/closing
ядром шире штриха → отдаёт штрихи целиком, любой полярности; порог Otsu по отклику). `text_mask_tile`
собирает маску из глифов, а не заливает прямоугольник. Прямоугольные «призраки» ушли, фон
между/внутри букв сохранён.

**Объединение reuse + text через пер-региональный `kind` — СДЕЛАНО.** Вместо глобального
переключателя каждая рамка несёт **тип** (`TimedRegion.kind`), три варианта:
- `"object"` — лого/графика: затираем **весь бокс** + reuse фона, пере-затираем при движении фона;
- `"text"` — субтитры/подписи: Vision-глифы, стираем **только буквы** (фон между ними цел);
- `"static"` — окклюдер на **неподвижном** фоне: затёрли один раз (или взяли реальный фон из паузы)
  и **заморозили плиту** на все кадры, без ре-проверки каёмки/keyint. Самое быстрое (≈1 проход
  LaMa) и без мерцания; даёт «наклейку», если фон за рамкой реально двигается. В воркере это
  object-путь с `can_reuse = r["seen"]` (без ring/keyint) + захват плиты даже при `--reuse 0`.

Воркер: **один проход** `flush_regions` диспетчеризует по `kind` — object-рамки идут по
box+reuse-пути (`run_region_lama`, статическая маска тайла), text-рамки — по Vision-глиф-пути
(`run_region_lama_masks`, покадровая маска); оба типа могут соседствовать в одном кадре и
композятся в один `out`. Глобальный флаг `--text` убран; `kind` идёт в regions-JSON. Осталась
глобальная галка `--reuse` (оптимизация только для object-рамок) и `--text-dilate`.

GUI: тип задаётся **в редакторе областей** — combobox «Тип рамки: Об'єкт/лого ↔ Текст/субтитри»
на выбранную рамку (`region_editor._on_kind_changed` → `TimedRegion.kind`). Глобальная галка
«Затирати лише текст» убрана; галка reuse переименована («для рамок Об'єкт/лого»). `lama.py`
STAT-лог показывает строку про reuse только когда reuse_reg>0.

**Проверено end-to-end** (`inpaint_video`, BALANCED, 2 рамки — object на титрах + text на
«Fake button gang», один прогон): титры затёрты (object+reuse 46%), текст — Vision-глифами,
оба в одном проходе, без ошибок.

## Перф кодирования — замеры и решения (M2)

Бенчмарк на 10-с 1440×2560 (декод+энкод, `bin/ffmpeg`):
- **Аппаратный декод (`-hwaccel videotoolbox`) — МЕДЛЕННЕЕ софтверного** (2.88 c против 0.60 c):
  софт-декодер на M2 быстр, а VT добавляет выгрузку кадров из медиа-движка. Пробовали — откатили.
- **libx264 `medium` = 11.1 c; `veryfast` = 5.25 c; `h264_videotoolbox` = 5.12 c.** Т.е. `veryfast`
  ~2× быстрее `medium` и при этом **лучше сжимает, чем VT** (файл меньше). Вывод: для пере-кодирования
  быстрый пресет выгоднее аппаратного.

Сделано:
- `video_encoder_args` читает `OutputConfig.preset` (дефолт **`veryfast`**, было жёстко `medium`) —
  ускоряет ВСЕ энкоды (воркер затирания, delogo, render).
- `render_video`: если видео не трансформируется (нет масштаба/burn-субтитров/смены fps) и кодек
  источника совпадает с целевым — **`-c:v copy` (ремукс), а не второй полный энкод**. Для removal-only
  (cleaned.mp4 уже H.264) это убрало лишний ~45-с энкод (стало 0.05 c). Проверено.
- GUI: комбо **«Кодування»** в шаге удаления (viewfast / medium / Апаратно VT) → `OutputConfig.preset`
  + `hw_encode`. Раньше выбор кодека был только в секции вывода, которая на шаге удаления скрыта.

**Сегмент-only (кодировать только интервал, остальное копировать) — НЕ делаем.** Стрим-копия склейка
требует совпадения кодека кусков и сегмента. Источники (YouTube/Insta) в основном **AV1/VP9**, а выход
H.264 → весь ролик всё равно транскодится AV1→H.264, копировать нечего. Помогло бы только для H.264-
источников; ради этого городить кейфрейм-склейку не стоит.

**Отложено в `stash@{0}`:** эксперимент «1-3» (аппаратный VideoToolbox декод/энкод + полнокадровый
пайп). **Откачен:** полнокадровый сырой пайп через ядро вызвал скачок `kernel_task` и лаги UI.
Как есть не восстанавливать; только lever-3 (VT-энкод) можно вернуть отдельно и аккуратно.

**Конвенция по коммитам:** коммитим **локально**; `git push` — только по явной просьбе.

## Громкость оригинала под озвучкой + пересборка звука без перекодирования

**Зачем:** раньше была только галка «оставить фон» с жёстко зашитым `volume=0.2`, и поменять
уровень можно было лишь полным перегоном (перекод видео + повторный TTS). Теперь это **уровень**,
и его можно **переставить на уже готовом видео за секунды**.

- `TranslateConfig.background_volume` (0..1) — линейная громкость **оригинальной** дорожки под
  дубляжем; `0.0` = только озвучка (заменяем звук, дефолт), `0.2` = музыка тихо под голосом,
  `1.0` = оригинал в полную. `keep_background` теперь **производное свойство** (`> 0`) — обратная
  совместимость. В GUI (`_tts_section`) вместо чекбокса — ползунок «Оригінал під озвучкою: 0–100%».
- Микс в `ffmpeg.render_video` вынесен в хелпер `_duck_mix`: `volume=<bg>` + `amix ... normalize=0`
  + `alimiter`. Раньше дефолтный `amix` **делил дубляж пополам** — теперь голос на полном уровне,
  а лимитер страхует сумму от клиппинга. **Это меняет громкость** старого keep-background пути.
- `ffmpeg.remix_audio()` — пересобирает **только звук** на готовом рендере: видео `-c:v copy`,
  аудио заново из двух стемов (оригинал из исходника, ducked до `bg_volume`, + кэшированный дубляж).
  Пишет во временный файл → `replace` (можно перезаписывать тот же выходной файл на месте).
- Кэш стемов: `runner` сохраняет собранный `dub.wav` в workspace (`ws.dub_file`, `Source/dub.wav`,
  перезаписывается каждым рендером), поэтому пересборка **не гоняет TTS заново**.
- GUI: `RemixWorker` (`gui/worker.py`) + кнопка «Пересобрати звук останнього відео» (активна после
  рендера с озвучкой). `_arm_remix` запоминает `{output, source, dub, bitrate, container}`; клик
  берёт текущий уровень ползунка и перемиксует последний вывод на месте. Требует workspace (в нём
  лежит `dub.wav`) — без него кнопка выключена. Проверено на реальном ffmpeg: уровень оригинала
  масштабируется линейно (≈+20 дБ на ×10 усиления), при `0` оригинал отсутствует, видео не перекодируется.

## Редактор субтитрів — капшени як єдине джерело для burn і озвучки

**Навіщо:** старе меню «Стиль субтитрів» (глобальний шрифт/розмір/колір/позиція) прибрано.
Замість нього — **візуальний редактор** `vidloc/gui/subtitle_editor.py` (`SubtitleEditor`),
за механікою рамок+таймлайну з `region_editor.py` (той самий H.264-проксі-плеєр: плавний
скраб + jog-audio). Крок «Субтитри» стоїть окремо від кроку «Озвучення».

**Ключова ідея:** список `Caption` (`vidloc/models.py`: text + start/end + `rect` позиції +
опційні per-caption оверрайди стилю) живе в `TranslateConfig.captions` і є **єдиним джерелом
правди і для вшитих субтитрів, і для дубляжу**. Редагуєш субтитр → змінюється і burn, і те, що
говорить озвучка (вимога користувача: «озвучка від тексту, що на екрані»).

- Рамку рухаєш/розтягуєш → позиція тексту; **висота рамки масштабує шрифт** (`BOX_FONT_FACTOR`=0.5
  в `ass.py`; редактор і ASS рахують однаково → WYSIWYG). Панель справа: текст, час, шрифт,
  жирність, розмір (%/авто), обведення, вирівнювання, колір, КАПС — на обрану репліку;
  «Застосувати стиль до всіх» копіює оверрайди.
- Кнопка **«Підтягнути переклад»** → `TranslateWorker` (`gui/worker.py`) перекладає кешований
  ASR-транскрипт і сідить капшени. Переклад кешується у workspace
  (`Text Analysis/<model>/translated_<mt>.json`, методи `load/save_translation`).
- Спільний хелпер перекладу винесено у `vidloc/translate/service.py: translate_for_job()`
  (звуть і runner, і воркер — не дублюємо логіку Aya/Dragoman/NLLB з фолбеками).
- Рендер капшенів: `subtitles/ass.py: write_ass_captions()` — per-caption `\pos`+`\an` з рамки
  та інлайн-оверрайди стилю. Стара `write_ass` лишилась для авто-фолбеку.
- Пайплайн (`pipeline/runner.py`): якщо `job.has_captions` → субтитри вшиваються з капшенів,
  а `dub_source` будується **з капшенів** (не з сирих сегментів). `needs_asr` при цьому False —
  прогін пропускає audio/ASR/translate. Без капшенів (CLI / редактор не відкривали) — старий
  авто-шлях ASR→translate→rechunk.
- GUI: галка soft/burn прибрана — субтитри завжди burn через редактор. Крок «Субтитри»
  доступний і в режимі «Тільки озвучка» (капшени керують дубляжем, але не вшиваються).

**Розбиття на короткі + збереження темпу озвучки (`Caption.group`).** Кнопка/меню «Розбити на
короткі» ріже репліку на шматки по ~3–4 слова (час розподіляється пропорційно довжині), усі
шматки дістають спільний `group` id. Субтитри вшиваються **окремими короткими рядками**, але
`runner._captions_to_dub()` **зливає групу назад в одну репліку** (текст цілком, span від першого
до останнього), тож TTS синтезує ціле речення — темп не «рубається» на 3-слівні фрагменти.
Незгруповані капшени (group=None) лишаються окремими одиницями озвучки.

**Позиціонування в кадрі.** Хіт-тест канви (`_CaptionCanvas._hit_order`) перевіряє спершу
**обрану**, потім **активні** на playhead рамки — інакше reverse-ітерація хапала останню з
рамок, що лежать одна на одній (усі капшени після «Підтягнути» мають однаковий bottom-rect →
рухалась не та). Малюються теж лише активні + обрана (решту не видно і не схопиш — спершу обери/
проскрабай до репліки). «Застосувати до всіх» копіює **і стиль, і `rect`** (позицію).

**Компроміс:** капшен = одиниця показу; для TTS одиниця — група (або окремий капшен). «Підтягнути
переклад» ріже на рівні речень (природна просодія); дрібніше — «Розбити на короткі».

## Шрифти субтитрів — реєстрація в Qt + бібліотека

**Був баг:** шрифти з `assets/fonts/` віддавались лише libass (burn через `fontsdir`), а в Qt
не реєструвались → у превʼю редактора `QFont(...)` мовчки падав на дефолт, і вибір шрифту нічого
не змінював. Виправлено: `vidloc/gui/fonts.py: load()` реєструє всі шрифти через
`QFontDatabase.addApplicationFont` (виклик у `app.py: main()` після `QApplication`) і повертає
список родин (кирилиця перша). Комбобокс шрифтів у редакторі будується з цього списку динамічно.

**Ключове — узгодженість імен:** значення в комбо (`cap.font`) використовується І для Qt-превʼю,
І для ASS `\fn`. Тому всі шрифти **нормалізовані** (name ID 1 == full name, subfamily "Regular",
унікальна родина на файл) — Qt і libass резолвлять один і той самий файл без неоднозначності
багатоважільних родин. Тому кожна вага = окрема родина в списку («Roboto», «Roboto Black», …).

**Бібліотека (25 родин, усі з повною укр. кирилицею — А, Ї, Ґ, Є, і):** Montserrat / Roboto /
Open Sans / Fira Sans / Inter / Rubik / Manrope / Nunito / Golos Text / PT Sans / PT Serif /
Oswald / Russo One / Unbounded — усі OFL з google/fonts. Тягне/оновлює скрипт
`scripts/fetch_fonts.py` (`uv run --with fonttools python scripts/fetch_fonts.py`): статичні —
завантажує, варіативні — інстансує в фіксовану вагу (повне покриття гліфів зберігається), потім
нормалізує імена. `assets/fonts/` у git (~6.5 МБ). Обведення у превʼю тепер теж масштабується
з `Caption.outline_w` (передаємо `video_w/h` у редактор; `BOX_FONT_FACTOR`/0.11 як в ASS).

## Завантаження з Instagram — потрібні куки браузера

Instagram більше **не віддає відео анонімно** (yt-dlp: «Instagram sent an empty media response…
login required»). Тому `vidloc/media/fetch.py` для cookie-gated хостів (`_COOKIE_HOSTS`:
instagram/facebook/threads) робить **retry з куками браузера** (`_run_ydl` → `cookiesfrombrowser`):
пробує анонімно, потім по черзі встановлені браузери (`_installed_browsers`: safari → firefox →
chrome → brave → edge → …). Користувач має бути **залогінений в Instagram** у якомусь із них.
- **Safari** читається лише з дозволом macOS «Повний доступ до диска» для терміналу/застосунку
  (інакше `Operation not permitted`) → рекомендуємо **Chrome/Firefox**. Chrome при читанні куків
  просить доступ до Keychain (Chrome Safe Storage) — це очікувано.
- **GUI (для звичайного користувача, без env):** у секції «Вхідне відео» — рядок «Instagram-вхід»
  з вибором браузера (Авто / Chrome / Firefox / Safari / … / файл cookies.txt) і кнопкою
  «Перевірити». Вибір зберігається у `~/.vidloc/config.json` (`vidloc/config.py`; `settings.CONFIG_DIR`).
  «Перевірити» → `CookieCheckWorker` → `fetch.check_cookies()`: **локальна перевірка без мережі**
  (читає куки браузера через `yt_dlp.cookies.extract_cookies_from_browser` і шукає `instagram.com`
  `sessionid`) — миттєво каже «сесію знайдено ✓» / «увійди в Instagram» / «Safari потребує Повний
  доступ до диска».
- Пріоритет джерела кук (`fetch._resolve_cookie_source`): env (`VIDLOC_COOKIES_BROWSER` /
  `VIDLOC_COOKIES_FILE`) → потім GUI-конфіг → потім авто-детект. При невдачі — дружня помилка
  українською (`_friendly_error`). YouTube/TikTok не зачіпаються (анонімний шлях).

**Перевірено:** headless-збірка вікна/редактора, `write_ass_captions` реально прожарено через
libass (позиції + per-caption стиль на кадрі коректні), boot GUI. НЕ прогнано на живому відео з
ML-моделями (pull-translation + фінальний рендер із дубляжем) — це наступний ручний тест.

## Окружение

- Зависимости: `uv` (Python 3.11; см. `.python-version`, `pyproject.toml`, `uv.lock`).

## Несколько venv — это намеренно

В проекте несколько окружений: `.venv` (ядро) + `.venv-styletts2`, `.venv-tts`,
`.venv-uktts`, `.venv-piper`, `.venv-f5`, `.venv-inpaint`. Движки озвучки и inpainting
конфликтуют по зависимостям с ядром и между собой, поэтому вынесены в отдельные venv. Все
они в `.gitignore`.

Команды установки вспомогательных TTS-venv (ставить только нужные):

```sh
uv venv .venv-styletts2 --python 3.11
uv pip install --python .venv-styletts2/bin/python \
  soundfile librosa scipy einops einops_exts munch pyyaml torch torchaudio \

  git+https://github.com/patriotyk/ukrainian-word-stress.git \
  git+https://github.com/patriotyk/ipa-uk.git \
  git+https://github.com/patriotyk/styletts2-inference.git

uv venv .venv-uktts --python 3.11
uv pip install --python .venv-uktts/bin/python ukrainian-tts

uv venv .venv-piper --python 3.11
uv pip install --python .venv-piper/bin/python piper-tts onnxruntime ukrainian-word-stress
```

## Если соберёшься делать репозиторий публичным

Проект сильнее всего смотрится как «движок локализации видео» (ASR → перевод → TTS → ffmpeg) —
это и стоит показывать в портфолио. Функцию удаления вотермарок лучше не выносить в публичную
витрину (вопросы авторских прав). Перед публикацией проверить лицензии шрифтов в `assets/`.
