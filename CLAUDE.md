## Что это

Vidloc — локальный десктопный локализатор видео для macOS (Apple Silicon).
Перевод EN/RU/IT → украинский: субтитры и озвучка; в работе — удаление вотермарок и вшитых
субтитров. Всё работает офлайн, без отправки данных в сеть.

## Текущий статус

- **Phase 1** (распознавание → перевод → субтитры): готово, протестировано end-to-end.
- **Phase 1b** (озвучка/дубляж: StyleTTS2-Ukrainian / ukrainian-tts / Piper /
  Coqui / F5-TTS): в работе.
- **Phase 2** (удаление вотермарок / вшитых субтитров): работает в GUI как **пошаговый мастер**:
  - workspace-кэш (`vidloc/workspace.py`): скачанный исходник + ASR-транскрипт по моделям →
    повтор того же видео не качает/не распознаёт заново.
  - распознавание — отдельный шаг (выбор модели → «Розпізнати» с busy-баром → исчезает;
    есть «Пропустити»).
  - удаление — **per-region, time-gated**: `TimedRegion` (rect + интервалы); редактор
    рамок+времени `vidloc/gui/region_editor.py` (до 15 рамок, ресайз/удаление ×, таймлайн
    со скобками, скраб-превью). Затирание (LaMa) идёт **только в размеченные интервалы**.

## Где мы остановились — reuse-first v1: ВСТРОЕНО в воркер

**Проблема:** профилировка инпейнта — **LaMa ≈ 94%** времени (декод/энкод/склейка ≈ 6%).
Имеет смысл сокращать только **число запусков LaMa**, а не ускорять её саму.

**Идея:** видео темпорально избыточно — фон за вотермаркой почти всегда виден в соседних
кадрах. Статичный угол-лого: LaMa один раз → дальше reuse. Для **временных** субтитров
чистый фон виден в паузах → плита **реальная** (не оценка) → потенциально ~0 LaMa.

**Урок прототипа:** авто-детекция «что и когда убирать» — хрупкая. **НЕ авто-детектить** —
движок ведём от **разметки пользователя** (регион + интервалы).

**Что реализовано (`vidloc/inpaint/lama_worker.py`, per-region, без motion-comp):**
- На каждый регион держим `plate` (чистый фон его рамки), `ref_ring` (снимок немаскированной
  каёмки вокруг рамки в момент захвата плиты), `seen`, `reuse_run`.
- Кадр, где рамка региона **не активна** → она реально видна → захватываем **реальную** плиту
  + свежий `ref_ring` (главный выигрыш для gated-субтитров).
- Кадр, где рамка **активна** и плита есть → сверяем текущую каёмку с `ref_ring`. Остаток мал
  (фон не сдвинулся) → заполняем из плиты, **без LaMa**. Остаток велик (движение/склейка/свет)
  → LaMa + переотметка плиты и `ref_ring`. Плиты нет → LaMa.
- Каёмка (`_ring`) — это «предохранитель» от артефактов вместо motion-comp. Кейфрейм-рефреш
  раз в `--reuse-keyint` reuse-ов (по умолчанию 120) против дрейфа.
- **LaMa гоняется по-регионным тайлам, а не по union-кропу.** ffmpeg-I/O по-прежнему режет
  один union-кроп (полнокадровый сырой пайп откатан — скачок `kernel_task`), но модель
  инпейнтит **тайл на регион** (box + `LAMA_CTX`=48 контекста), батчем по кадрам этого региона
  (группировка `pending` → `jobs[id(r)]` → `run_region_lama`). Так стоимость LaMa растёт по
  площади регионов, а не по описывающему прямоугольнику: при разбросанных регионах union почти
  весь кадр, а тайлы маленькие. Кадры эмитятся по порядку.
- Параметры воркера: `--reuse {0,1}` (0 = старое поведение, LaMa на каждый активный кадр),
  `--reuse-thresh` (0.02, mean|Δ| на каёмке 0..1), `--reuse-pad` (6), `--reuse-gap` (2),
  `--reuse-keyint` (120). `lama.py` пробрасывает reuse/thresh/keyint и логирует строку `STAT`.
  Тумблер reuse проброшен в GUI (`RemovalConfig.reuse`, чекбокс в шаге удаления, вкл. по
  умолчанию) → `inpaint_video` → `lama.py`. `lama.py` при падении воркера кладёт в текст
  ошибки хвост его вывода (раньше traceback глотался и в лог попадала одна строка).
- **Вся reuse-работа bbox-локальна** (`r["bb"]` = box+feather+ring): на 1440p кроп — это
  миллионы пикселей, и полнокадровые numpy-операции на регион были бы неподъёмны.
- Счётчики в `STAT`: `lama_reg`/`reuse_reg` (порегионные решения) + `gpu_frames` (кадров,
  реально ушедших в LaMa — это и есть драйвер времени) + `frames`.

**Баг, который правили (был краш на реальном прогоне):** `if r in active` — это проверка
вхождения по значению, а регион — dict с numpy-полями; когда у двух регионов **совпадают
`intervals`** (частый случай: два вотермарка на всё видео, или двухстрочная полоса субтитров),
`dict.__eq__` доходил до numpy-ключа и падал с «truth value of an array is ambiguous». Смоук на
1 регионе это не ловил. Заменено на список флагов `acts` (без membership по значению).

**Замеры:**
- smoke `5bQxK0XldVg.mp4` (622 кадра 1080×320, scale=2): reuse=1 → gpu≈76, ~24 c; reuse=0 →
  622, ~107 c. **≈4.5× быстрее**, картинка неотличима от full-LaMa.
- `For Test.mp4` (1440×2560, 1 регион, весь клип 2748 кадров): **gpu_frames=176/2748,
  reuse 94%** — лучший случай (статичный фон, gated). Кодирование в реальном времени.
- `For Test.mp4` (8 разбросанных регионов, union-кроп 1242×1926), 6-с обрезка 360 кадров:
  **union-LaMa → ~560 c**; **per-region тайлы → ~69 c (≈8×)** при тех же решениях reuse
  (gpu_frames=320, reuse_reg=453; lama_reg=991). Артефактов/швов от тайлов нет.

**Вывод по перфу:** узкое место на разбросанных многорегионных 1440p был **не** число кадров,
а площадь, уходящая в LaMa на каждом кадре (union-кроп ≈ весь кадр). Тайлинг это снял (≈8×).
reuse отдельно максимально выигрывает на статике/gated (кадр целиком мимо LaMa, до 94%).

**Следующие шаги:**
1. ✅ *Сделано:* по-регионные тайлы вместо union-LaMa (≈8× на разбросанных регионах).
2. Проверить reuse на **реальной** разметке gated-субтитров (одна нижняя полоса + паузы) — там
   ждём высокий кадровый reuse (в паузах берём реальную плиту).
3. v2 — motion-comp / гомография по каёмке: когда фон **сдвинут** (а не сменился), варпить
   плиту вместо LaMa. Включать только после того, как v1 докажет чистоту на реальном контенте.
4. Возможная доработка тайлинга: исключать чужие box'ы из контекста тайла (сейчас соседний
   активный регион может попасть в контекст LaMa как «фон») + группировать близкие регионы в
   один тайл, чтобы не гонять перекрывающиеся тайлы.

## Text-mode: затирание по буквам (Apple Vision), НАЧАТО

**Зачем:** на текстурном фоне (текст поверх лого/картинки) затирание всего прямоугольника
рвёт фон в мыло. Решение: внутри рамки детектить **сам текст** и затирать только его пиксели —
LaMa работает в идеальном режиме (маленькие дырки в реальном фоне). Связка: «где» задаёт
рамка пользователя (надёжно), «что именно» — нейросеть.

**Что реализовано:**
- `vidloc/inpaint/vision_text.py` — детектор текста через **Apple Vision** (Neural Engine,
  офлайн), из numpy-кадра в память (без PNG на диск). Standalone (без `vidloc`-импортов),
  воркер тянет его как **sibling** (`import vision_text`, т.к. запускается из своей папки).
  Нужен `pyobjc` (Vision+Quartz) в `.venv-inpaint` — **поставлен через `uv pip`** (в скрипт
  создания venv пока НЕ добавлено — см. «известный пробел»).
- Воркер: флаг `--text {0,1}` (+`--text-dilate` 4). `flush_batch` разведён на `flush_reuse`
  (старый путь, `--text 0`, без изменений) и `flush_text`. В text-режиме на каждый активный
  кадр: детект текста в боксе → тайл-маска глифов → батч по-кадровых масок через LaMa на тайле
  региона → композитим только пиксели текста. reuse в этом режиме отключён (маска мелкая,
  LaMa дёшева). При отсутствии pyobjc воркер падает с понятной ошибкой (→ fallback delogo).

**Замер (6-с обрезка `For Test.mp4`, рамка на «Fake button gang» поверх лого Jeep, scale=2):**
`--text 1` → 360 кадров за ~26 c, текст стёрт, **лого/фактура руля сохранены** (у прямоугольного
затирания на том же месте — мыло). Детект отработал в 358/360 кадрах.

**Глифовая маска (шаг 2) — СДЕЛАНО:** `vision_text.glyph_mask()` внутри каждого найденного
word-бокса заливает **сами штрихи** через морфологический **tophat/blackhat** (opening/closing
ядром шире штриха → отдаёт штрихи целиком, любой полярности; порог Otsu по отклику). `text_mask_tile`
собирает маску из глифов, а не заливает прямоугольник. Прямоугольные «призраки» ушли, фон
между/внутри букв сохранён.

**Важно (был баг v1):** первая версия маски считала «отклонение от размытого фона» — это по сути
детектор **краёв**: давал контур буквы, а тело оставалось → на тесте текст оставался читаемым.
Заменено на tophat/blackhat (заливает тело штриха). Проверка: белый текст на чёрном покрывается
~целиком, дырки букв сохраняются. `se_frac` (размер морфо-ядра, дефолт 0.5·высоты) пока
внутренний (не выведен в CLI/GUI).

**Объединение reuse + text через пер-региональный `kind` — СДЕЛАНО.** Вместо глобального
переключателя каждая рамка несёт **тип** (`TimedRegion.kind`), три варианта:
- `"object"` — лого/графика: затираем **весь бокс** + reuse фона, пере-затираем при движении фона;
- `"text"` — субтитры/подписи: Vision-глифы, стираем **только буквы** (фон между ними цел);
- `"static"` — окклюдер на **неподвижном** фоне: затёрли один раз (или взяли реальный фон из паузы)
  и **заморозили плиту** на все кадры, без ре-проверки каёмки/keyint. Самое быстрое (≈1 проход
  LaMa) и без мерцания; даёт «наклейку», если фон за рамкой реально двигается. В воркере это
  object-путь с `can_reuse = r["seen"]` (без ring/keyint) + захват плиты даже при `--reuse 0`.

Воркер: **один проход** `flush_regions` диспетчеризует по `kind` — object-рамки идут по
box+reuse-пути (`run_region_lama`, статическая маска тайла), text-рамки — по Vision-глиф-пути
(`run_region_lama_masks`, покадровая маска); оба типа могут соседствовать в одном кадре и
композятся в один `out`. Глобальный флаг `--text` убран; `kind` идёт в regions-JSON. Осталась
глобальная галка `--reuse` (оптимизация только для object-рамок) и `--text-dilate`.

GUI: тип задаётся **в редакторе областей** — combobox «Тип рамки: Об'єкт/лого ↔ Текст/субтитри»
на выбранную рамку (`region_editor._on_kind_changed` → `TimedRegion.kind`). Глобальная галка
«Затирати лише текст» убрана; галка reuse переименована («для рамок Об'єкт/лого»). `lama.py`
STAT-лог показывает строку про reuse только когда reuse_reg>0.

**Проверено end-to-end** (`inpaint_video`, BALANCED, 2 рамки — object на титрах + text на
«Fake button gang», один прогон): титры затёрты (object+reuse 46%), текст — Vision-глифами,
оба в одном проходе, без ошибок.

**Что НЕ доделано (следующие шаги text-mode):**
1. **Темпоральное сглаживание** маски по кадрам (сейчас детект/сегментация независимы покадрово
   → край может мерцать на видео). Например EMA маски или медиана по 3 кадрам.
2. Эмодзи/графика Vision-ом как текст не ловятся (для чисто текста это ок).
3. Тюнинг `glyph_mask` (k, дилатация) и, при желании, char-boxes Vision вместо word-boxes.

## Перф кодирования — замеры и решения (M2)

Бенчмарк на 10-с 1440×2560 (декод+энкод, `bin/ffmpeg`):
- **Аппаратный декод (`-hwaccel videotoolbox`) — МЕДЛЕННЕЕ софтверного** (2.88 c против 0.60 c):
  софт-декодер на M2 быстр, а VT добавляет выгрузку кадров из медиа-движка. Пробовали — откатили.
- **libx264 `medium` = 11.1 c; `veryfast` = 5.25 c; `h264_videotoolbox` = 5.12 c.** Т.е. `veryfast`
  ~2× быстрее `medium` и при этом **лучше сжимает, чем VT** (файл меньше). Вывод: для пере-кодирования
  быстрый пресет выгоднее аппаратного.

Сделано:
- `video_encoder_args` читает `OutputConfig.preset` (дефолт **`veryfast`**, было жёстко `medium`) —
  ускоряет ВСЕ энкоды (воркер затирания, delogo, render).
- `render_video`: если видео не трансформируется (нет масштаба/burn-субтитров/смены fps) и кодек
  источника совпадает с целевым — **`-c:v copy` (ремукс), а не второй полный энкод**. Для removal-only
  (cleaned.mp4 уже H.264) это убрало лишний ~45-с энкод (стало 0.05 c). Проверено.
- GUI: комбо **«Кодування»** в шаге удаления (viewfast / medium / Апаратно VT) → `OutputConfig.preset`
  + `hw_encode`. Раньше выбор кодека был только в секции вывода, которая на шаге удаления скрыта.

**Сегмент-only (кодировать только интервал, остальное копировать) — НЕ делаем.** Стрим-копия склейка
требует совпадения кодека кусков и сегмента. Источники (YouTube/Insta) в основном **AV1/VP9**, а выход
H.264 → весь ролик всё равно транскодится AV1→H.264, копировать нечего. Помогло бы только для H.264-
источников; ради этого городить кейфрейм-склейку не стоит.

**Отложено в `stash@{0}`:** эксперимент «1-3» (аппаратный VideoToolbox декод/энкод + полнокадровый
пайп). **Откачен:** полнокадровый сырой пайп через ядро вызвал скачок `kernel_task` и лаги UI.
Как есть не восстанавливать; только lever-3 (VT-энкод) можно вернуть отдельно и аккуратно.

**Конвенция по коммитам:** коммитим **локально**; `git push` — только по явной просьбе.

## Озвучка и перевод — актуальный апгрейд

- Основной TTS-движок по умолчанию: **StyleTTS2-Ukrainian**,
  `patriotyk/styletts2_ukrainian_multispeaker_hifigan`, worker
  `vidloc/tts/styletts2_worker.py`, venv `.venv-styletts2`. Голоса берутся из Space

  экспериментальный `f5_uk`: worker `vidloc/tts/f5_worker.py`, venv `.venv-f5`,
  reference wav берётся из `tts_clone_reference` или из первого ASR-сегмента исходного видео.
- TTS по-прежнему запускается только subprocess-воркерами в своих venv. Не импортировать
  StyleTTS2/F5/Coqui/Piper/ukrainian-tts в основную `.venv`.
- Перевод по умолчанию остаётся **Aya** (`TranslateQuality.NATURAL`,
  `mlx-community/aya-expanse-8b-4bit`). NLLB `fast/best` не менялись. Добавлен спец-режим
  **Dragoman** (`TranslateQuality.DRAGOMAN`, `lang-uk/dragoman-4bit`) только EN→UK;
  для RU/IT или при ошибке загрузки/генерации pipeline мягко откатывается на Aya.

- GUI: `./run.sh` (PySide6).

- Полный список флагов CLI — в `README.md`.

## Окружение

- Зависимости: `uv` (Python 3.11; см. `.python-version`, `pyproject.toml`, `uv.lock`).
- Ускорение: Apple Silicon MPS/Metal (mlx-whisper для ASR, torch MPS для NLLB-200).

- Модели — в `models/` (~26 ГБ), в git НЕ входят, тянутся автоматически при первом запуске.

## Что НЕ коммитим (уже в .gitignore)

`models/`, `work/`, `output/`, `bin/`, все `.venv*`, `__pycache__`, `.DS_Store`,
`.claude/settings.local.json`. Это либо тяжёлое, либо генерируемое заново.

## Если соберёшься делать репозиторий публичным

Проект сильнее всего смотрится как «движок локализации видео» (ASR → перевод → TTS → ffmpeg) —
это и стоит показывать в портфолио. Функцию удаления вотермарок лучше не выносить в публичную
витрину (вопросы авторских прав). Перед публикацией проверить лицензии шрифтов в `assets/`.
